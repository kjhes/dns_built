Nmap(Network Mapper)
- 내 컴퓨터에서 어떤 포트가 열려 있는지 탐색하는 스캐닝 도구
- 보안 점검에서는 사용하지 않는 포트가 열려 있는지 찾아봄 (선제적인 보안 취약점 진단)

Npcap(Nmap packet capture) 
- 컴퓨터를 오가는 데이터(패킷)를 직접 가로채서 전달하는 수집 엔진
- Nmap 의 일부 검사와 Wireshark와 같은 분석 도구가 실시간 트래픽을 감시할 수 있도록 기반 제공

Wireshark
- 수집한 네트워크 데이터(패킷의 세부 내용)를 화면에서 자세히 살펴보는 도구
- 보안 점검에서는 접속 과정과 요청 · 응답에 이상한 점이 있는지 확인
- 해킹 / 악성코드 트래픽 추적 및 암호화 되지 않은 민감 정보 노출 여부 점검

Traffic
-네트워크에서 컴퓨터들 사이에서 오고가는 데이터의 양이나 흐름 
-트래픽을 분석한다는 것은 네트워크 상에서 오가는 데이터들을 관찰하며 이상 징후(해킹, 악성코드, 정보 유출 등)가 이뤄지고 있는지 검색 하는 것

<TCP 3-Way Handshake 과정>
1. SYN (Synchornize Sequence 
。클라이언트 -> 서버
。"나랑 연결할래? 내 번호는 100번이야." 하고 연결 요청을 보냄.

2.SYN - ACK (Synchornize-Acknowledgement
SYN - ACK 은 서버가 클라이언트의 연결 요청을 수락하면서, 동시에 자신도 통신할 준비가 되었음을 알리는 쌍방향 확인 신호
。서버 -> 클아이언트
。"어, 확인했어(ACK)! 네가 보낸 100번 잘 받았으니 다음엔 101번 보내줘. 그리고 나도 너랑 연결하고 싶어.
내 번호는 2000번이야(SYN)." 하고 응답.

3.ACK (Acknowledgment)
。클라이언트 -> 서버
。"나도 확인했어! 그럼 2001번 보낼게. 연결 시작하자!" 하고 최종 확정

*SYN 은 연결 요청(Request),ACK는 확인 응답(Response)

*ACK 번호는 받은 번호 + 1 임. "여기까지 받았으니 다음 거 줘" 라는 뜻
*100, 2000 은 그냥 예시고 실제로는 랜덤한 숫자로 시작함 (번호 예측해서 끼어드는 거 막으려고)
*3번까지 끝나야 연결 완료 -> 그 다음부터 진짜 데이터 주고받음
